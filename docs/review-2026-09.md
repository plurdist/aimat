## Scope and method

- **Baseline:** `main` at `db926f2`, which is byte-identical to the local `aimat-0.1.6` wheel, plus the uncommitted Continuator work. The only code that's new since 0.1.6 is the Continuator.
- **Out of scope:** RAVE (waiting on an architecture decision, AIM2-33). Model chaining as a feature belongs to the *Model chaining* project. The folder-based chain that exists today is covered by AIM2-11.
- **Reproductions:**
  - Ran the listener's logic with the OSC client and `subprocess.run` stubbed, so no containers or shell commands were executed.
  - Ran the published `plurdist/aimat-continuator:arm-latest` image on `test.mid`.
  - Ran `continuate.py` against current upstream Continuator in a scratch virtual environment.
- **Line references** in the Linear comments point at the working tree *before* the Continuator tidy-up in this PR. Lines from 66 onwards in `osc_listener.py` have since moved by about +1, and the Continuator handler got shorter.

## 3. Continuator: commit decision

**Committed in this PR, with small changes.** The published image works end to end: `continuate.py` on `test.mid` with the listener's arguments exits 0 and writes a MIDI file. The script in the image matches `resources/scripts/continuator/continuate.py` byte for byte.

Changes made before committing, none of which alter behaviour:
- `Dockerfile.continuator`: pinned upstream to `9e71270` and documented the build context (repo root).
- `osc_listener.py`: removed commented-out code, an unused variable and a stale container name, and added Continuator to the blinker's message list.
- `README.md`: documented `/trigger_model continuator`, its output folder and its current limitations, and fixed the GIF links after the `examples/` → `resources/examples/` move.

Deliberately **not** fixed here: AIM2-8, 9, 11, 35 and 36 in the Continuator handler. They share the pattern of the other three models and should be fixed test-first through AIM2-41.

Not committed: `test.mid` and the `.DS_Store` changes.

## 4. Recommendations

1. **Do AIM2-41 first.** One refactor into a job runner plus per-model adapters gives every later fix a place to land and makes the OSC-boundary tests (AIM2-14) possible. Otherwise AIM2-6, 8, 9, 11, 35 and 39 each get patched four times.
2. **Introduce a job/result contract over OSC:** a job id, per-job input and output paths, and `/status`, `/done` and `/error` replies keyed to the job. This fixes the root cause of AIM2-6, 9, 11, 35 and 39, and it's the hand-off contract that *Model chaining* (AIM2-28) needs anyway.
3. **Make images reproducible before pinning them** (AIM2-37, then AIM2-12 and AIM2-13). The Continuator rebuild failure shows the drift risk is already real. Recover the missing build inputs from the published images while they still exist.
4. **Report results honestly.** Several findings (AIM2-6, 9, 36, 38) come down to reporting success without checking. These are the Legibility failures FOCAL targets, and they're cheap to test at the OSC boundary.
5. **The new *Model containerisation toolkit* project** (backlog) should build on items 1 to 3: a module spec plus a template is what AIM2-41's adapter interface and AIM2-37's reproducible Dockerfiles turn into.
